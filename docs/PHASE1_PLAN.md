# Phase 1 — แผนงาน (ปรับใหม่ 2026-09-28)

แผนนี้แทนที่ขอบเขต Phase 1 เดิมที่อยู่ใน commit history (ระบบแต้ม, merge สมาชิกเดิม,
auto-match ออเดอร์, ผูกบัญชีแพลตฟอร์ม) ซึ่ง **ไม่อยู่ใน Phase 1 อีกต่อไป**

## เป้าหมาย

ยืนยันตัวตนว่าลูกค้าเคยซื้อสินค้าจริง เพื่อใช้สิทธิ์รับประกันเท่านั้น
**ไม่มีการสะสมแต้มใน Phase นี้**

## ขอบเขต

1. **หน้าลงทะเบียนใน LINE OA (LIFF)** — ลูกค้ากรอกข้อมูลและใส่เลขคำสั่งซื้อตามช่องทาง
2. **บันทึกเข้า Supabase ไว้เฉยๆ** — ไม่มีการ merge ข้อมูล, ไม่ auto-match, ไม่ให้แต้ม
3. **Dashboard CRM หลังบ้าน** — ใช้ดูข้อมูลสมาชิกและรายการลงทะเบียน

## หน้าฟอร์ม: 2 Flow

### Flow A — ก่อนลงทะเบียน

- อ้างอิง `index.html` บน branch `main` (สำเนาเดียวกับ `legacy/index.html`)
  **เอาทุกอย่างเหมือนไฟล์นี้ ห้ามคิดเอง** — layout, ลำดับ section, ข้อความ, ตัวเลือก,
  การ validate, modal เงื่อนไขการรับประกัน, หน้าสำเร็จ
- ช่องทางตาม `index.html`: Shopee, Lazada, TikTok, HomePro, Makro Pro, ใบเสร็จ
  — กรอกหมายเลขคำสั่งซื้อ/เลขที่ใบเสร็จ
- **ส่วนที่เพิ่มจาก `index.html` (ตัดสินใจแล้ว):** ช่องทาง **Facebook** และ **LINE**
  - ไม่ต้องกรอกเลขคำสั่งซื้อ
  - แสดง checkbox แทนช่องกรอก:
    `[ ] ยืนยันคำสั่งซื้อด้วยเบอร์โทรกับที่สมัครสมาชิก`
  - เบอร์ที่ใช้อ้างอิงคำสั่งซื้อ = เบอร์โทรที่ลูกค้ากรอกด้านบนของฟอร์ม
    (ไม่มีช่องกรอกเบอร์ซ้ำ)
- ไม่มีการอัปโหลดรูปใบเสร็จ (ไม่มีใน `index.html`)

### Flow B — หลังลงทะเบียน

- แสดงประวัติข้อมูล: ข้อมูลสมาชิก และรายการที่เคยลงทะเบียนรับประกัน
- ปุ่ม **ลงทะเบียนสินค้าเพิ่ม** → เปิดฟอร์มโดยข้อมูลส่วนตัวถูกกรอกและล็อกไว้แล้ว
  กรอกแค่ช่องทาง + เลขคำสั่งซื้อ (พฤติกรรมเดียวกับสมาชิกเดิมใน `index.html`)

## ของที่สร้างไว้แล้วแต่ **เก็บไว้ ไม่ใช้ใน Phase 1** (ตัดสินใจแล้ว)

ไม่ลบตาราง/ฟังก์ชันออกจาก Supabase แต่ต้องไม่มีโค้ด Phase 1 เรียกใช้ และไม่แสดงใน UI:

- แต้ม/ระดับ: `ht_points_config`, `ht_tiers`, `ht_points_ledger`, `ht_finalize_registration`,
  `/api/liff/points`, หน้า "สิทธิพิเศษ"
- Merge สมาชิกเดิม: `ht_merge_members`, `ht_relink_requests`, `ht_approve_relink_request`,
  `/api/liff/relink`, ปุ่ม "เคยเป็นสมาชิกแล้ว?"
- ผูกบัญชีแพลตฟอร์ม: `ht_member_platform_accounts`, `bind-account.ts`
- Auto-match กับ `sales_transaction` ตอนลูกค้าส่งฟอร์ม (`resolve.ts`)

## ใช้ต่อจากของเดิม

- ยืนยันตัวตน LINE ฝั่ง server (`src/lib/liff/`) — line_uid มาจาก ID token ที่ตรวจแล้วเท่านั้น
- `ht_members`, `ht_warranty_registrations`, บันทึกการยอมรับเงื่อนไข (`ht_member_consents`)
- Dashboard: login พนักงาน, `/customers` (ต้องซ่อนส่วนแต้มและปุ่ม merge)

## คำถามที่ยังเปิดอยู่

- ข้อความเงื่อนไขการรับประกัน: ใช้ตาม `index.html` (12 เดือน) — ยืนยันว่าไม่ใช้ข้อความ
  "365 วันต่อ SKU" ที่เขียนไว้ใน seed เดิม
- สถานะรายการลงทะเบียน: ทุกรายการเป็น "รอตรวจสอบ" แล้วให้แอดมินเปลี่ยนสถานะใน
  dashboard หรือแค่ดูข้อมูลอย่างเดียว
